## Безопасность бэкенда и пределы передачи

- JSON-ответы бэкенда ограничены **8 MiB**, тела ошибок — **64 KiB**. Проверяется Content-Length, но также считаются реальные байты, включая chunked-передачу и ложную длину.
- Буферизованные и потоковые медиа (HTTP 200 и 206) ограничены `maxMediaBytes` на одну передачу. Один Range сокращается до этого лимита с сохранением начала (либо сокращается суффикс); некорректные/многодиапазонные запросы и несогласованный `Content-Range` отклоняются. Поиск в больших файлах через ограниченные диапазоны сохраняется. HEAD не скачивает тело, тело 416 отбрасывается.
- `connectTimeoutMs` действует до конца передачи медиа, а не только до заголовков. При превышении лимита, отказе или отмене потока получателем тело upstream закрывается. Ошибка после отправки заголовков закрывает загрузку без JSON-ответа.
- Все HTTP-интерфейсы бэкенда, включая загрузку файлов и повтор через `/api`, отказываются следовать перенаправлениям (`redirect`); указывайте конечный URL сервера. Нативное WebSocket-подключение прогресса также не следует перенаправлениям.
- Отмена прерывает текущий запрос history. Даже при одновременной ошибке history плагин ждёт попытки адресного `cancelPrompt` до статуса killed/interrupted и удаления отслеживания. Очистка best-effort: недоступный бэкенд может продолжить работу. Прерывается лишь prompt, который очередь подтверждает как текущий; чужие задачи намеренно не останавливаются.
- Origin медиа берётся только из Host разрешённого запроса и протокола сервера, не из Referer. Резервный адрес — конкретный bind; поиск LAN применяется только при wildcard-bind. Файл ассета удаляется лишь при явно заданном абсолютном, доступном `outputDir`; иначе удаляется только запись индекса.

Версия **0.6.4** — локальное исправление имён скачиваемых медиа, пока не опубликованное. Перед установкой из файла ниже выполните `npm pack`. Интерфейс по умолчанию русский; выбор английского сохраняется, прежний `zh` заменяется на русский. Описания инструментов и сопутствующий навык — на английском, с указанием отвечать пользователю по-русски по умолчанию.

## Возможности

### Инструменты агента

Агент работает с ComfyUI напрямую, вручную на холсте ничего делать не нужно:

- `comfyui_run` — отправляет workflow в API-формате или встроенный шаблон (txt2img / img2img / video) и возвращает сгенерированные медиа; `mode: "sync"` ждёт результат, `mode: "async"` запускает фоновую задачу (настоятельно рекомендуется для видео).
- `comfyui_object_info` — список определений нод, поддерживаемых сервером, чтобы агент мог собрать корректный workflow на месте.
- `comfyui_workflow` — библиотека workflow плагина: `list` (адрес сервера, локальные каталоги ComfyUI, содержимое зоны загрузки, параметры каждого workflow), `run` (запуск по id с переопределением параметров), `skill` (по запросу читает пакет навыков workflow), `refresh` (пересчитывает снимок параметров).
- `comfyui_skill` — чтение и запись пакетов навыков (`list` / `read` / `write` / `append` / `mkdir` / `rename` / `delete` / `enable` / `require`): агент может записать найденные грабли в пакет и использовать опыт в других сессиях.

### Панель UI

Закреплённая справа панель с тремя вкладками:

- **Workflow** — библиотека запускаемых workflow (создание / редактирование / запуск / удаление / импорт `.json`, теги и фильтр). **Экспорт / импорт пресетов**: выбранные workflow (по умолчанию все; строки с пакетом навыков помечены) упаковываются вместе с параметрами и пакетами навыков в `.zip`; после экспорта показывается отчёт со списком упакованных workflow, именем файла, размером и предупреждениями. Пресет можно **перетащить в окно чата** (или выбрать файл): он анализируется целиком и импортируется выборочно, пакеты навыков восстанавливаются байт в байт (даже большие шаблоны на тысячи файлов); импорт всегда создаёт новые workflow и не перезаписывает существующие. Графовые workflow, сохранённые в ComfyUI, находятся автоматически и могут быть **извлечены** в запускаемые (если на холсте несколько независимых цепочек — целиком / по компонентам / только основную).
- **Ассеты** — все результаты генерации: просмотр, скачивание, удаление по наведению (файл в выходном каталоге ComfyUI удаляется, только если задан `outputDir`; иначе удаляется лишь запись).
- **Очередь** — живая очередь и история задач в пяти состояниях: удаление / прерывание / повторный запуск / очистка / освобождение памяти; у задач плагина есть прогресс-бар и превью.

При нажатии кнопки «Панель ComfyUI» в заголовке сессии проверяется связь бэкенда с ComfyUI. Если связи нет, панель сворачивается (кнопка не подсвечивается), а вверху страницы появляется уведомление с причиной и подсказкой запустить локальный ComfyUI (чтобы бэкенд увидел порт) или проверить адрес удалённого сервера в настройках. Когда всё в порядке, ничего не показывается; при восстановлении связи ненадолго появляется «Соединение в норме».


### Параметры LoRA (0.6.3)

Для точного класса `Power Lora Loader (rgthree)` и входов `lora_N` распознаются объектные параметры `type: lora`. Редактор: включение, файл, сила модели и необязательная сила CLIP; пустая сила CLIP означает `null` (наследовать силу модели). Списки файлов берутся из `LoraLoader`, затем `LoraLoaderModelOnly`, `LoraLoaderBypass`, `LoraLoaderBypassModelOnly`. Авторский недоступный файл сохраняется до явного изменения. `refresh` обновляет списки, сохраняя тип и значения. Сохранение, редактирование и экспорт/импорт пресетов сохраняют объекты.

Агент передаёт частичное переопределение, например `{"lora_1":{"on":false,"strength":0,"strengthTwo":null}}`. Разрешены только `on` (boolean), `lora` (string), `strength` (конечное число), `strengthTwo` (конечное число или null). Они сливаются с авторским объектом; незнакомые авторские поля сохраняются. Пустые объект/строка ничего не меняют, пропущенный параметр использует сохранённое значение. Некорректные, неизвестные и опасные поля отвергаются; старый строковый параметр больше не может затереть объект. «Дополнительно» поддерживает только примитивы и эти строки LoRA, не произвольные объекты. После обновления перезапустите DSH и заново распознайте параметры уже извлечённого процесса; если строки были потеряны старым конвертером, переизвлеките оригинальный граф.

### Извлечение именованных виджетов (0.6.2)

Графы с `widgets_values_named` преобразуются по явному соответствию имени и значения, без позиционного сопоставления. Подключённые входы имеют приоритет; служебные divider/header/кнопка добавления и `control_after_generate` не попадают в API. Power Lora Loader от rgthree поддерживает нумерованные входы `lora_*`, сохраняя on/off, силы и null для силы CLIP. Корректная именованная карта считается полной: отсутствующие ключи не угадываются по позиционному массиву (отсутствующие обязательные входы вызывают ошибку извлечения). Некорректный контейнер карты включает прежнее преобразование; некорректные именованные значения LoRA вызывают явную ошибку. Без именованной карты сохраняется прежний путь, включая DynamicCombo и управление seed. Исправлено извлечение; доступность моделей и генерация этим не проверяются.

### Зона загрузки (загрузчик медиа)

Загрузчик медиа на странице workflow по образцу ноды LoadImage в ComfyUI: визуальный выбор изображений / видео / аудио (с прослушиванием на месте), вставка из буфера, несколько слотов. Положенные материалы по порядку подставляются в параметры загрузки workflow, не заданные явно, — **агенту не нужно угадывать имена файлов**; если `width`/`height` не переданы, берётся разрешение исходного изображения. Загружаемые файлы именуются по хэшу содержимого (дубликаты не плодятся).

Поле `loadArea` в `comfyui_workflow list` сообщает агенту число слотов и их содержимое.

### Пакеты навыков workflow (инструкция для агента)

Список параметров говорит агенту только «какие есть ручки», но не «для чего этот workflow и где он ломается». К сложному workflow можно прикрепить **пакет навыков** (кнопка «Пакет навыков» на карточке workflow):

```
<каталог данных>/skills/<workflow>/
  SKILL.md          # основной документ: когда применять / ключевые параметры / предостережения
  references/       # справочные материалы: подборки стилей, записи об ошибках
  assets/           # референсные изображения и т.п. (с превью в панели)
```

- **Раскрытие в три уровня, без постоянного места в контексте**: в `comfyui_workflow list` — одна строка описания → для выбранного workflow `action: skill` отдаёт основной текст → отдельный справочный документ читается, только когда текст на него ссылается. Даже десятки workflow с полной документацией в обычном диалоге стоят по одной строке.
- **Редактирование в панели**: слева список файлов, справа редактор; импорт (раскладка по каталогам по расширению), свои подкаталоги, превью изображений, перенос всего каталога пакетов на другой диск или в синхронизируемую папку (настройка «Каталог пакетов навыков»).
- **Агент тоже может писать**: инструмент `comfyui_skill` позволяет агенту читать и редактировать пакет — наткнулся на проблему, дописал её через `append` в SKILL.md, и в следующий раз (в том числе в другой сессии) опыт уже есть.
- **Обязательно к прочтению**: при включённом флажке «Прочитать перед запуском» вызов `run` отклоняется, пока агент в этой сессии не прочитал пакет навыков.

### Медиапрокси и настройки

Скачивание медиа (0.6.4) предлагает исходное имя ComfyUI, а не `media.png`: каждый ответ содержит локально сформированный `Content-Disposition` с ASCII-вариантом и UTF-8 `filename*`. Пассивные медиа остаются inline; активные и неизвестные типы — attachment/octet-stream с sandbox и nosniff. Пути, управляющие символы, опасная пунктуация и имена устройств очищаются; длинные имена ограничены 180 байтами UTF-8 с сохранением обычного расширения. Ссылки карточек уже передают исходное имя; панель и lightbox используют имя ответа, включая старые URL history/index. Случайного переименования нет. Одинаковые имена в разных подпапках (или после очистки) могут совпасть: браузер/менеджер загрузок решает, добавлять суффикс или перезаписывать. После обновления перезапустите приложение и перезагрузите страницу; кешированный ответ может ещё не содержать новый заголовок.

Сгенерированные файлы отдаются через маршрут того же origin (`/comfyui/media`) по имени файла и не зависят от хранящейся в памяти истории ComfyUI — старые результаты открываются и после перезапуска или очистки истории. Браузер не обращается к ComfyUI напрямую: нет CORS, нет смешанного контента, API-ключ в браузер не передаётся. Все маршруты `/comfyui/*` проходят ту же проверку доступа, что и `/api` DSH.

На странице настроек появляется раздел «ComfyUI»: адрес сервера, имя переменной окружения с API-ключом, локальные каталоги ComfyUI, адрес доступа к медиа, проверка соединения, язык интерфейса. Изменения применяются сразу, править `cordis.yml` не нужно.

## Установка

```sh
# профиль web
dsh plugin --profile web add ./oin111-dsh-comfyui-0.6.4.tgz
# профиль desktop
dsh plugin --profile desktop add ./oin111-dsh-comfyui-0.6.4.tgz
```

После перезапуска приложения в боковой панели появится вход в панель, в настройках — раздел «ComfyUI», а агент сразу получит все инструменты и сопутствующий skill.

## Использование

Просто скажите агенту, например:

- «Нарисуй в ComfyUI рыжего кота»
- «Переделай эту картинку в стиле киберпанк»
- «Преврати аниме-картинку из зоны загрузки в реалистичное фото с тем же разрешением»
- «Сгенерируй 5-секундное видео: город на закате»
- «Запусти Krea-Afterlight, который я раньше сохранил в ComfyUI» (если граф ещё не извлечён, агент попросит сначала нажать **Извлечь** в панели)

Если удалённый ComfyUI стоит за прокси с аутентификацией, ключ передаётся через хранилище учётных данных или переменную окружения, указанную в `apiKeyEnv` (по умолчанию `COMFYUI_API_KEY`), и никогда не уходит в браузер.

## Настройка

Секция `comfyui` в `cordis.yml` (большую часть можно менять на странице настроек):

| Ключ | По умолчанию | Описание |
| --- | --- | --- |
| `baseUrl` | `http://127.0.0.1:8188` | Адрес сервера ComfyUI |
| `apiKeyEnv` | `COMFYUI_API_KEY` | Имя переменной окружения / учётных данных с необязательным API-ключом |
| `dataDir` | *(каталог данных DSH)* | Где хранятся библиотека workflow и индекс ассетов |
| `comfyuiDirs` | `[]` | Локальные каталоги установки ComfyUI (можно несколько); по ним агент находит модели, пользовательские ноды, библиотеки голосов TTS |
| `outputDir` | `''` | Выходной каталог ComfyUI (абсолютный путь). Файлы при удалении ассета удаляются только здесь; пусто — удаляется только запись в панели, файлы остаются |
| `mediaHost` | `''` (авто) | Внешний базовый адрес для сгенерированных медиа. Пусто — хост последнего прошедшего проверку запроса браузера, затем адрес, на котором слушает веб-сервер (LAN-IP угадывается только при привязке к `0.0.0.0` / `::`) |
| `skillsDir` | `''` (по умолчанию `dataDir/skills`) | Корень пакетов навыков (абсолютный путь; подойдёт синхронизируемая папка или репозиторий) |

## Требования

- DeepSeek Harness (профиль `web` / `desktop`)
- Запущенный сервер [ComfyUI](https://github.com/comfystack/ComfyUI) (по умолчанию `http://127.0.0.1:8188`)
- Для шаблона `video` нужны [ComfyUI-WanVideoWrapper](https://github.com/kijai/ComfyUI-WanVideoWrapper) и модель Wan 2.1
