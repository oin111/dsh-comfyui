# Local concurrency and lifecycle rebuild

This work was reimplemented from the published `modernize-0.2` baseline
`ffacff47c83cf854d2f82f7edb510c525b58cfcf` (package version 0.6.5). It is a new
source snapshot, not a recovery or verification of the lost unpublished commit
`043668e`. No version bump, remote push, release, npm publication, or installation
on a user's host is part of this change.

## Changes

- Workflow create/edit/delete/skill mutations serialize on the canonical library
  path across store instances. Complete JSON snapshots replace the destination
  atomically, with exclusive temporary-file creation and cleanup on failure.
  Corrupt library reads fail without replacing the existing file. The lock is
  process/module-local, not a cross-process database lock; the data-directory
  ancestry must remain trusted and stable.
- Parameter application caches node definitions by normalized server address
  and resolved credential fingerprint. A plugin-scoped bounded cache shares
  concurrent loads. Settings updates and explicit voice/parameter refreshes
  invalidate old flights; their late completion cannot restore stale cache data.
  Explicit discovery/editor reads remain fresh so newly uploaded media is visible.
- Client creation snapshots endpoint, credential reference and request limits
  before credential resolution. A config change cannot attach an old credential
  to a new server. Tool queueing and completion polling use the same client.
- Queue state writes are serialized/coalesced and unchanged state is not written
  again. Tracked runs and archive markers are bounded together. Concurrent sweeps
  share one operation; removed/replaced runs cannot gain stale archive markers.
- Task-center polling waits for every request to settle, including partial
  failures. Hidden tabs pause polling; visibility/filter changes request fresh
  results. Closing/hiding/refreshing aborts reads; a shared drain gate prevents
  overlap across remounts and React StrictMode replay, with a 30-second request
  deadline. Closed panels ignore late poll/action completions and repeated action
  clicks are gated.

## Checks

From a clean checkout, using Node >= 22.19:

```sh
npm ci
npm test
npm run typecheck
npm run test:localization:full
```

For a restricted environment without a writable home cache, pass
`--cache /path/to/writable/npm-cache` to `npm ci`. No global install is needed.

Targeted synthetic regressions are in:

- `scripts/test-workflow-concurrency.mjs`
- `scripts/test-object-info-cache.mjs`
- `scripts/test-runtime-races.mjs`
- `scripts/test-queue-tracker.mjs`
- `scripts/test-queue-polling.mjs`

These cover concurrent saves (including 20 across path aliases), atomic JSON
reads, failed writes, cache coalescing/isolation/refresh races, asynchronous
credential resolution, tracker persistence and UI lifecycle behavior. The
existing host-contract suite also explicitly admits DSH 0.2.1-rc.2.

The exact public baseline store was also probed separately: all 20 concurrent
saves returned success, but only one workflow survived. The rebuilt store keeps
all 20, including writes through separate instances and directory aliases.

Full tests, typecheck and full RU/EN localization checks passed on the rebuild.
Host-contract stubs and component-level UI tests are not GPU generation, a full
browser session, or proof of PTC sandbox compatibility. Separate real-host mock
integration uses DSH 0.2.1-rc.2; report its actual result separately. No private
workflows, real credentials or generated user media are used by these new tests.
